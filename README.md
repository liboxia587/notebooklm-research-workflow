# 用 NotebookLM 做出可信、可用的调研报告

一套从寻找原始资料，到提炼、核验、整合报告的研究流程。

适用于行业研究、竞品分析、产品调研、选址评估、专题学习等任务。你只需要替换研究主题，按步骤推进。

**目标：资料覆盖充分、信息及时、分析有深度，结论有证据。**

> 状态：v0.1 公开试用版。欢迎用真实任务测试，并通过 GitHub Issues 反馈问题。本流程不保证穷尽所有资料，也不把 AI 自查视为独立核验。

## 你最终会得到什么

只保留三个核心成果：

- **主报告**：面向使用者回答问题，说明结论、依据、条件和下一步。
- **证据表**：记录每项关键结论的来源、适用范围及不确定性。
- **来源清单**：保留原始链接、发布机构、日期与获取状态。

整个过程持续修订同一份主稿，避免多个版本互相矛盾。

## 流程总览

**定义需求 → 建立资料地图 → 寻找原始资料 → 提炼证据 → 去伪存真 → 整合报告 → 使用反馈**

发现关键资料缺失，就定向补搜；发现结论依据不足，就回到原文核验。

开始前设置时间、费用和补搜轮次上限。达到上限后交付已有成果与未解决问题，不无限循环。

## 第一步：明确要解决什么问题

填写以下内容；不知道的标注“待明确”，不要让 AI 替你编造。

```text
研究主题：
报告给谁使用：
要支持什么决策或任务：
必须回答的问题（3—5个）：
地域、对象与时间范围：
已有资料：
时间与费用预算：
```

然后发送：

```text
根据以上需求，建立研究问题清单与资料搜集地图。
每个子问题列出：所需证据、原始发布机构、检索词及同义词、
需要覆盖的不同立场，以及容易遗漏的内容。
指出必须澄清的条件，先不要写报告或预设结论。
```

## 第二步：快速寻找原始资料

采用三轮检索，而不是无目的地堆积文章：

| 轮次 | 操作 | 输出 |
| --- | --- | --- |
| 广搜定位 | 用综述、专业文章发现术语、机构和引用 | 资料地图与检索线索 |
| 追溯原件 | 沿链接、脚注、作者及完整标题寻找原始发布页 | 原始文件、数据、研究 |
| 定向补缺 | 找最新版本、反例、失败案例和遗漏对象 | 缺口与分歧的补充证据 |

常用搜索写法：`关键词 site:机构域名`、`"完整报告标题"`、`关键词 数据集 方法 附录`。适合时交叉使用中英文关键词。

在可联网检索的工具中使用：

```text
按照资料地图寻找原始来源。每条返回标题、原始发布者、原文链接、
发布日期、数据覆盖期、对应问题及关键价值。
区分已读全文、仅有摘要、仅发现链接；识别重复转载与商业宣传。
同一底层数据的多篇文章不算独立证据。最后列出尚未覆盖的问题。
```

搜集时检查五件事：

- **全**：关键问题和证据类型是否覆盖，而非文章数量是否够多。
- **新**：同时看发布日期、数据发生时间和版本；新文章可能引用旧数据。
- **深**：是否包含方法、原始数据、机制解释与局限。
- **广**：是否覆盖不同对象、立场、成功及失败案例。
- **准**：来源、口径和引用能否核实；一手资料也可能存在偏差。

保留“基础研究＋最新进展＋原始数据或案例＋反方证据”。搜索摘要只作线索，重要材料要读原文。

## 第三步：放入 NotebookLM，提炼证据

导入可获取的资料，并确认当前选中的来源符合本轮任务。不要上传未经授权的敏感材料。

```text
仅基于当前资料，按研究问题建立证据表：
研究问题｜核心主张｜支撑证据与引用位置｜方法｜适用时间与范围｜
局限｜矛盾或缺失信息｜对使用者的意义。
严格区分事实、作者观点、你的推断和待验证假设。
保留重要分歧。此前AI生成的回答不能作为独立证据。
```

提炼不仅要保留“结论是什么”，还要保留“为什么成立、在什么条件下成立”。

## 第四步：去伪存真

```text
审查证据表：引用是否直接支持主张？来源是否独立？是否过时、
断章取义或口径冲突？是否把相关性当因果、把个案当规律？
将结论标为：证据较充分／有条件支持／存在争议／证据不足，并说明理由。
优先列出最可能改变最终判断的核验事项，以及需要补充的原始证据。
不要用未经核实的比例、评分或阈值替代缺失数据。
```

人工打开支持核心结论的原文，核对关键数字、日期、定义和适用条件。AI 自查可以发现疑点，但不能代替这一步。

存在关键缺口时，只补搜相关资料，再更新证据表。

## 第五步：生成并修订一份主报告

```text
面向【使用者】，为其完成【决策或任务】，整合已核验内容。
结构：核心结论、逐项分析、证据与推理、适用条件、风险与不确定性、
下一步行动。关键事实和数字附引用。
缺失信息不得补造；示例与实测结果分开；分歧不得强行统一。
正文控制在【字数】，证据表和来源清单放附录。
最后检查结论是否超出证据，直接修订这份主稿，不另写重复报告。
```

涉及计算时，用表格或代码实际验证。文字中写了公式，不代表文件已经实现或计算正确。

## 什么时候可以交付

- 关键问题都有回答，或明确说明为什么暂时不能回答。
- 核心结论可以追溯到原文。
- 日期、单位、统计口径和适用范围一致。
- 重要分歧与缺口已说明。
- 没有把示例、推测和未知信息写成事实。
- 使用者能看懂下一步该做什么。

## 试用案例：新店选址调研

研究问题是“如何评估具体铺位是否适合开店”。流程应覆盖需求、竞争、客流、物业条件及单店经济测算。

试用中需要警惕：把品牌经验当通用规则、把固定租销比当统一标准、把示例销量当实测结果，以及把未经验证的公式当成可用工具。

没有真实点位数据时，合理交付是**方法框架、空白模板和调查清单**，不能生成确定的开店结论。
